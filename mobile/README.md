# Membership Management System mobile apps

Android is ready for local builds. The iPhone source and project specification are prepared for Xcode on a Mac. Both use the existing HTTPS website and its database; these are connected apps and require internet access. No server credentials or database backups are bundled into either app.

## Install the Android test app

The Windows build creates `artifacts/android/membership-management-debug.apk` in the repository root. Copy it to an Android phone and open it to install. Android may ask you to allow installation from the browser/file manager you used. This debug APK is for testing, not a Play Store release. The app supports Android 8.0 and newer and needs a current Android System WebView.

Sign in with your existing account. The server chooses the correct admin, manager, employee, trainer or member dashboard. Allow camera access when scanning a QR. The system file picker handles photos and documents without granting access to all files. Downloaded passes and reports use a Save dialog. Receipt printing opens Android Print/Save as PDF. The app's generic blue membership icon is used on the home screen; each organization retains its own logo after login.

Website changes become visible in the app when its pages reload. Native code, app icon, app ID, version, permission, or website-origin changes require a new app build. Existing session expiry and subscription restrictions remain enforced by the server. The app does not offer offline attendance or offline payments.

## Where to edit

- **VS Code:** existing `app/` and `lib/` folders for dashboards and business logic.
- **VS Code or Android Studio:** `mobile/android/app/src/main/java/com/digigraptek/membership/` for Android integrations.
- **Android Studio:** open the `mobile/android` folder, sync Gradle, select a device and click Run. Use **Build > Generate Signed App Bundle or APK** for your release.
- **Xcode on a Mac:** generate and open the project described below for iPhone testing/signing.

## Shared app identity

Edit `mobile/app.config.json`:

- `appName`: Membership Management System.
- `appId`: `com.digigraptek.membership` (choose the final ID before first store publication).
- `websiteUrl`: the live HTTPS website. The native shells keep only that exact origin inside their authenticated view.
- `versionName` / `versionCode`: increase these for updates.

Android reads this configuration at build time. Run the iPhone preparation command again after changing it. No Android/iOS store account, signing key or production release was created by this setup.

## Android commands on Windows

Requirements: Android Studio with its bundled JDK, Android SDK Platform 37.0 and Build Tools 36.0.0. The repository pins Android Gradle Plugin 9.4.1 and Gradle 9.6.0. The build script detects the standard Android Studio and SDK install locations; set `JAVA_HOME` and `ANDROID_HOME` for a custom installation.

```powershell
npm.cmd run app:android:build
npm.cmd run app:android:check
```

To install via USB, enable USB debugging on the phone and run your SDK's `platform-tools/adb.exe install -r artifacts/android/membership-management-debug.apk`.

Release preparation: open Android Studio, use **Generate Signed App Bundle or APK**, and create/choose your own release keystore. Keep the keystore and passwords outside Git. `npm.cmd run app:android:bundle` creates a release bundle but does not configure release signing by itself. Play Console publication additionally needs your developer account, privacy-policy URL, data-safety declarations, screenshots, content rating and device testing.

## iPhone preparation

On a Mac with Xcode and XcodeGen installed:

```sh
npm ci
npm run app:ios:prepare
cd mobile/ios
xcodegen generate
open MembershipManagement.xcodeproj
```

Choose your Apple developer team in **Signing & Capabilities**, select a simulator or iPhone, then Run. Use **Product > Archive** for TestFlight/App Store distribution. The initial source targets iOS 16+ and includes the website configuration, persistent WKWebView cookies, QR camera permission prompt, file downloads, receipt printing and offline retry. It has not been compiled or tested on an iPhone in this Windows environment. Validate camera access, picker/download flows, printing and layout on a real device before distribution. Store review/approval is a separate step.

`project.yml` and `MembershipApp/Info.plist` are generated by `app:ios:prepare`. `MembershipApp/Assets.xcassets` contains a generic app icon. Organization logos continue to come from the server.

## Verification before release

1. Sign in/out with every role and confirm expired/disabled accounts are denied.
2. Test trainer assignment, branch transfer and member visibility without changing production test subjects accidentally.
3. Test QR scanning with camera allowed, denied and re-enabled; test image scanning too.
4. Upload a profile picture, save a QR pass and report, and print/save a receipt as PDF.
5. Check keyboard, Android back button, small screens, landscape and app resume.
6. Disconnect the internet, use Retry, and verify background refreshes remain silent.

Native projects and APKs are excluded from Vercel's web build upload. Build outputs, IDE caches and signing material are ignored by Git. Existing web deployment commands remain unchanged.
